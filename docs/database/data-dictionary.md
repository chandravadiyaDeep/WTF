# NUMPA v2 — Candidate Data Dictionary

**Status:** Draft; candidate types/constraints for review, not migrations. All application IDs are UUID unless noted. Times are timestamptz; money is integer minor units plus ISO currency; token amounts are integer units unless a reviewed precision decision says otherwise. Tenant tables carry workspace_id and should have same-workspace composite FKs. RLS uses active workspace membership. created_by/requested_by are attribution, not ownership. “Retention” is policy-dependent; no durations are set here.

## Identity and workspace

| Table | Important columns and types | Keys, constraints, indexes | Ownership and retention |
|---|---|---|---|
| profiles | user_id uuid, display_name text, preferences jsonb bounded, created_at/updated_at timestamptz, deleted_at timestamptz | PK/FK user_id → auth.users.id; user_id immutable; preferences allowlisted | Auth identity, not workspace-owned. Minimal profile; delete/anonymize under account policy. |
| workspaces | id uuid, kind text, name text, personal_owner_id uuid nullable, organization_id uuid nullable later, created_by uuid, created_at, status | PK id; check kind personal/organization; personal_owner_id required only for personal; unique personal owner if one personal workspace/user; FK creator | Root tenant. Soft-close then deletion workflow; preserve billing/legal references as approved. |
| workspace_members | workspace_id uuid, user_id uuid, role text, status text, invited_by uuid nullable, joined_at, removed_at | PK (workspace_id,user_id); FKs workspace/profile; check role/status; index user_id,status and workspace_id,role | Membership grants access. Removal revokes immediately; retain minimal invitation/audit history by policy. |
| organizations (later) | id uuid, workspace_id uuid unique, legal/display name, status, created_at | PK id; unique workspace; FK to workspace; name/status checks | Organization maps to organization workspace; retain legal data per policy. |

### Cross-table integrity

- Foreign keys from workspace-scoped records must include workspace identity where feasible. Reject cross-tenant parent references.
- dataset_versions.parent_version_id and cleaning_executions input/output establish lineage; never update a completed version to point to different content.
- Profile and pipeline published versions are immutable and referenced by completed runs.
- Training/evaluation records capture exact dataset version, protocol, split-role manifest, algorithm/software/config versions. Keep training, validation, and test metrics distinct.
- reports.source_refs must be bounded and validated; for integrity-critical provenance, use typed FKs or report-source join rows instead of arbitrary JSON IDs.
- Every state with billing consequences has a unique idempotency key and trusted transition. Completed runs/results and posted ledger rows are append-only.
