## Lifecycle and control rules

1. Database and object storage changes are not one transaction: use pending states, retryable idempotent workers, and reconciliation of missing/orphaned objects.
2. RLS controls metadata; private Storage policies and authorization checks control bytes. Object keys are not permissions. Signed URLs are short-lived bearer credentials; never log or persist them in reports.
3. Browser storage may be cleared or evicted; device loss/profile changes can destroy data. Do not claim recovery unless cloud persistence was selected.
4. Deletion first blocks access and new work, revokes URL issuance, requests cancellation, then deletes objects and dependent rows asynchronously. Track completion and exceptions.
5. Keep raw rows and sensitive values out of summaries, evidence, worker diagnostics, and audit events unless a reviewed user need requires them.
6. Before implementation, approve retention durations, legal exceptions, regions, provider backup/PITR capability, deletion SLA, and recovery objectives.
